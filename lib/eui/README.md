# EUI 自绘窗口支持库（实验）

这是 [跨平台窗口方案](../../docs/跨平台窗口UI支持库实施方案.md) 的 Windows 纵向接入，不是三平台正式发布。保留 Win32 项目原有行为，不做自动迁移。

## 准备与使用

当前仅支持 **Windows x64 宿主与目标**。安装 Visual Studio C++ Build Tools，包含 MSVC x64、Windows SDK、C++ CMake 工具。

在仓库根目录执行：

```powershell
.\lib\eui\prepare-sdk.ps1
npm run build
npm run preview
```

准备脚本下载（或复用独立样例缓存）并校验固定 EUI-NEO v0.6.3 Windows x64 SDK：

- 上游 commit：`3f951ff1f47e4c9b50cdef59337a62f98c5490a8`。
- SHA-256：`6c15ed06a3b8cd9a5cbccac302a45a70fb43c68c925d9ecbe711dcc110bfbc8e`。
- 窗口/渲染后端：GLFW + OpenGL。

SDK 只放在本库的 `sdk` 目录，构建时不联网，也不读取外部源码目录。SDK 和独立 P0 开发目录不随正式 IDE 包发布；缺 SDK/工具链时，向导显示不可用原因。

新建 → Windows → 窗口程序 → 选择 EUI → 勾选实验确认，或直接打开 [EUI窗口示例.epp](../../examples/eui-window/EUI窗口示例.epp)。在工具箱选择“EUI自绘控件”，双击控件编辑事件，保存后编译/运行。示例说明见 [项目 README](../../examples/eui-window/README.md)。

## 已接通的语义

- 单项目单提供者；项目记录 `UiProvider`、API/插件版本、EUI 编译器；旧项目缺字段时仍为 Win32。
- EUI 控件保存 `libraryId`/`typeId`；拒绝混入 Win32 控件、未知属性、菜单以及未支持的源码类型，不静默丢弃功能。
- 支持窗口、按钮、单/多行编辑框、标签、图片框、复选框、单选框、滑块、进度条、分组框；保留适配控件的属性读写和创建/交互事件。
- `krnln` 核心控件只开放已实现的标准属性/事件；滑块和进度条支持最小/最大位置与当前位置，单选框按所在分组框分组（未放入分组框的单选项属于同一窗口默认组）。
- `webview2` 的网页按钮、网页编辑框在 EUI 项目中使用 EUI-NEO 主题控件呈现，不执行原 WebView HTML 模板；浏览框使用真实 WebView2 子窗口，随窗口尺寸/位置/可视/禁止状态更新，并在窗口销毁时由宿主回收。需要系统安装 Microsoft Edge WebView2 Runtime；地址仅接受 `http(s)://` 或 `about:blank`。
- 主窗口和子窗口使用无原生装饰的承载窗口，标题栏、窗口按钮、边框和客户区由 EUI 自绘；设计器不再套用 Win32 窗口样式。标题栏高度、按钮宽度、字体尺寸及配色来自同一份主题数据。窗口宽/高仍指客户区，原生承载高度额外包含自绘标题栏，控件坐标无需迁移。
- Windows 保留标题区域拖动/双击最大化、边缘缩放与工作区最大化；自绘按钮支持键盘最小化、最大化/还原、关闭。模态子窗口存在时，父窗口的系统移动/缩放/关闭等操作被阻止。
- `载入 (第二窗口, _启动窗口, 假)` 为非模态载入；标准 `载入` 必须显式第三参数为假。
- `EUI显示窗口 (“第二窗口”, 真)` 是**异步模态**，立即返回，仅限制主窗口输入；不等同 Win32 同步等待窗口关闭。当前仅支持主窗口作为 owner。
- `销毁 (第二窗口)` 后可再次载入；主窗口销毁后进程退出。
- 内嵌或本地图片部署到输出的 `assets/project-images`，单张不超过 50 MiB。编译失败不覆盖上一份成功输出。
- 运行时和设计器共享 [主题数据](theme-tokens.json)。修改后执行 `node .\lib\eui\generate-metadata.mjs`，同时提交生成的 JSON 和头文件。
- 设计器是明确标记的布局模拟；实际预览编译原生窗口，不执行用户事件源码。

输出位于项目的 `output\windows\x64`。运行时须保留同目录 `assets`；支持从其他工作目录启动。F5 目前普通运行并明确警告，不支持断点调试。

## 使用其他支持库的控件

选择 EUI 窗口不代表只能使用本库控件。其他已加载控件库只要声明兼容当前提供者、目标平台和已实现的运行适配，就能同时出现在工具箱中；无需贡献顶层窗口，也不会把自身身份改成 `eui`。

例如，其他库的窗口单元可以使用以下身份/适配字段，并按现有窗口单元格式补齐属性、事件和图标等元数据：

```json
{
  "name": "业务按钮",
  "englishName": "OrderButton",
  "uiProviders": ["ycide.eui.selfdraw"],
  "runtimeType": "EuiButton",
  "previewType": "按钮"
}
```

`.efw` 保存的是该库自己的 `libraryId` 和 `typeId=OrderButton`；`runtimeType` 只是复用 EUI 基础控件的呈现与交互，不是控件唯一标识。即使多个库有相同显示名、英文类型名，属性/事件、补全和编译绑定仍按库区分。缺少原控件库时不会自动替换成同名控件。

当前基础运行适配包括 `EuiButton`、`EuiInput`、`EuiLabel`、`EuiImage`、`EuiCheckbox`、`EuiRadio`、`EuiSlider`、`EuiProgress`、`EuiGroup`、`EuiWebView`、`EuiWebButton` 和 `EuiWebEdit`。核心库与 WebView2 单元在 EUI 工具箱中只显示对应适配实现的属性/事件；事件签名仍限无参数、无返回值。其他设计期属性或事件签名没有适配时构建明确报错。属性读写模板及需要的命令实现仍由控件自己的库提供，其实现文件会因控件被使用而参与链接；图片资源不再依赖控件的中文名称或归属库。

这不是把 Win32 原生控件无条件搬进自绘窗口，也不是已开放任意第三方绘制扩展；此类控件需要补齐实际适配后才能使用。

### 已适配的现有外库：脚本组件

加载随仓库提供的 `script` 库后，在 EUI 项目工具箱选择 **第三方组件 → 功能组件 → 脚本组件**。可放置并保存重开，编辑“语言”（JScript/VBScript 文本）和“超时”（有符号 32 位毫秒值，≤0 不限制），通过自身方法执行脚本：

```text
脚本组件1.执行 (“var total = 6 * 7;”)
EUI置文本 (“标签1”, 脚本组件1.计算表达式 (“total”))
```

使用 `runtimeType: EuiScript` 适配现有脚本库 ABI；“执行 / 计算表达式 / 运行 / 清除”及语言、超时、只读错误信息均由 `script` 实现，不是用 EUI 控件冒充。窗口创建事件前应用设计值，关闭时释放引擎状态，重开从设计值初始化；多个实例互不共享脚本变量。独立预览链接所需库，但不执行用户脚本或事件源码。

这是 **Windows 非可视功能组件**，设计器占位不在运行时绘制，也不创建原生子控件，不表示 JScript/VBScript 已跨平台。EUI 不展示尚未适配的 Win32 通用成员；Win32 项目原有组件与通用属性保持不变。

**其他已加载库不会因此自动兼容**：`krnln` 仅接入表格所列核心控件，未列出的 Win32 控件仍不会出现在 EUI 工具箱；`webview2` 也仅适配浏览框、网页按钮和网页编辑框。`spec`、`ycplugin` 不贡献窗口控件。完整实际支持矩阵见[方案第 5.2 节](../../docs/跨平台窗口UI支持库实施方案.md)。临时测试库不是交付控件，不作为“现有库已接入”的证明。

## 验证与剩余门槛

Windows 实测工具链：MSVC 19.51.36248，Visual Studio 18 BuildTools。相关测试：

```powershell
npx vitest run tests\unit\euiWindowIntegration.spec.ts tests\unit\pluginPhase2.spec.ts tests\unit\pluginKernel.spec.ts tests\unit\coreLibraryHashes.spec.ts tests\unit\controlCodegenSnapshot.spec.ts
npx playwright test window-ui-provider.spec.js
```

原生测试覆盖真实易语言属性/创建事件、子窗口销毁重载、图片复制、示例构建、编译失败保护和预览；隔离 Electron 测试覆盖新建、实验确认、保存重开、拒绝不兼容平台、键盘操作和浅深色对比。

跨库回归使用独立临时控件库（不写入产品支持库目录），与 EUI 库贡献同名、同英文类型名的按钮；验证自有属性 setter 实际执行、图片复制、工具箱绘制与事件选择、保存重开、缺库不替换，以及成员补全/诊断不串库。

实际产品库回归另使用 `script`：隔离 Electron 中放置脚本组件、用键盘编辑语言/超时、保存重开，在浅深色设计器中显示非可视组件占位；原生测试执行组件方法、读写属性、验证两实例隔离，以及关闭重开子窗口后脚本变量清除和设计超时恢复。

窗口外壳另有真实窗口探测：确认无原生 `WS_CAPTION`、原生非客户区高度为零、客户区逻辑尺寸不变；验证标题双击、标题/边缘命中测试和自绘按钮的键盘最小化/最大化/还原/关闭。通过仅捕获测试窗口的 `PrintWindow` 验证浅深色标题/客户区实际像素与共享主题 RGB 的误差不超过 3/255，不依赖全屏截图或全局键鼠操作。设计器测试核对浅深色标题背景、外壳高度、按钮宽度和客户区偏移。文字光栅化、字体资源和全部控件细节尚不承诺像素级一致，精确效果以实际预览为准。

**尚未开放**：Linux/macOS 运行时及编译适配、系统读屏桥接、完整原生键鼠/IME/多 DPI 验收、同步模态、完整控件/菜单/资源/类模块、第三方可执行窗口适配器。
