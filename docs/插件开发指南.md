# ycIDE 插件开发指南

本文面向第三方插件作者。设计依据见 `docs/插件架构设计稿.md`，模板在 `templates/plugins/`。

## 1. 插件是什么

一个插件就是一个目录，根目录下有一份清单 `plugin.json`：

```
yourname.hello/
  plugin.json     # 必需
  main.js         # JS 插件的入口（或可执行文件插件的 plugin.exe）
  ui/             # 网页编辑器等界面（可选）
  themes/         # 主题文件（可选）
```

插件有三种形态：

| 形态 | `runtime.type` | 运行在哪里 | 例子 |
|---|---|---|---|
| 数据插件 | 省略或 `none` | 不运行代码，IDE 直接读取 | 主题包、菜单 / 快捷键调整 |
| JS 插件 | `node` | 受限的插件进程（每个发布者一个） | 命令、AI 工具、编译器 |
| 可执行文件插件 | `executable` | 独立进程，经标准输入输出通信 | 用易语言、C++、Go 等写的插件 |

## 2. 清单 `plugin.json`

```jsonc
{
  "id": "yourname.hello",          // 发布者.名称：小写英文、数字、短横线；名称里不能有点
  "displayName": "你好插件",
  "version": "0.1.0",
  "publisher": "yourname",          // 必须与 id 的前缀一致；ycide 保留给官方
  "description": "……",
  "engines": { "ycide": ">=0.0.5" },
  "platforms": ["windows"],         // 可选：只在这些系统上加载（windows / linux / macos，可带 -x64 等后缀）
  "runtime": { "type": "node", "main": "main.js" },
  "activationEvents": ["onStartup"],// 可选：启动即激活；不写则在第一次执行它的命令时激活
  "permissions": ["workspace:read"],
  "dependencies": { "yourname.base": "^1.0.0" },
  "contributes": { … }
}
```

### 贡献点

| 贡献点 | 作用 |
|---|---|
| `commands` | 命令（`{ id, title, enablement? }`），JS / 可执行文件插件必须先在这里声明才能注册处理函数 |
| `menubarMenus`、`menus` | 标题栏菜单与菜单项（`menubar/tools` 等，`group` 为 `分组@顺序`） |
| `keybindings` | 快捷键（`{ command, key, when? }`） |
| `themes` | 主题（`{ id, path }`，文件格式同内置主题） |
| `aiProviders`、`aiTools` | AI 模型提供方、AI Agent 工具（工具由命令实现） |
| `compilers` | 编译器（由命令实现 build / run / stop） |
| `editors` | 编辑器（第三方只能用 `ui.type: "web"`，页面运行在沙箱 iframe 里） |
| `languages` | 文档语言 ID 与扩展名 |

`when` 表达式可以用的上下文键见设计稿 §6.1。

## 3. 权限

第三方插件只拥有清单里声明、并且用户同意过的权限。越权调用会失败，错误码 `-33001`。

| 权限 | 含义 |
|---|---|
| `workspace:read` | 读取项目里的文件和打开的文档（`ycide.documents.getText`） |
| `workspace:write` | 写入项目里的文件 |
| `documents:write` | 修改编辑器里打开的文档（`ycide.documents.applyEdit`） |
| `workbench:commands` | 执行 IDE 菜单里的功能（保存、编译、运行……）；调用其他插件的命令不需要权限 |
| `secrets:own` | 保存自己的密钥（`ycide.secrets`，加密存储，与其他插件隔离） |
| `ai:invoke` | 调用 AI 模型（预留） |
| `terminal` | 使用内置终端（预留） |
| `process:spawn` | 启动其他程序（**敏感**） |
| `fs:any` | 读写任意文件（**敏感**） |
| `net:<域名>` | 访问指定域名：`net:api.example.com`、`net:*.example.com`（含子域名）、`net:*`（**敏感**，任意网站） |

JS 插件的进程用 Node 权限模型做第二道防线：

- 只能读自己的插件目录，只能写自己的存储目录（`context.storagePath`），声明 `fs:any` 才放开；
- 不能启动子进程（声明 `process:spawn` 才放开），不能加载原生模块、不能开 Worker；
- 只能连接 `net:` 权限里的域名；
- 拿不到 IDE 的环境变量。

同一发布者的插件共用一个进程，进程级限制按它们权限的并集放开；宿主侧的权限检查仍按单个插件进行。

可执行文件插件以原生程序运行，系统层面不受限制。安装时 IDE 会明确告诉用户这一点。它调用 IDE 能力时仍受权限检查。

## 4. JS 插件 API

```js
exports.activate = (context, ycide) => {
  context.subscriptions.push(ycide.commands.registerCommand('hello:run', async (...args) => { … }))
}
exports.deactivate = () => {}
```

| API | 说明 |
|---|---|
| `context.pluginId` / `extensionPath` / `storagePath` | 插件 ID、插件目录、可写存储目录 |
| `context.subscriptions` | 停用时自动 `dispose()` |
| `ycide.commands.registerCommand(id, fn)` | 注册命令（必须在清单里声明过） |
| `ycide.commands.executeCommand(id, ...args)` | 执行任意命令（内置命令需要 `workbench:commands`） |
| `ycide.window.showMessage(text, type?)` | 输出面板消息，`type` 为 info / warning / error / success |
| `ycide.output.appendLine(text, type?)` | 编译输出面板追加一行 |
| `ycide.documents.getText(path)` | 读文档（含未保存修改），需要 `workspace:read` |
| `ycide.documents.applyEdit(path, text, baseText?)` | 改文档（在编辑器里显示差异，用户可撤销），需要 `documents:write` |
| `ycide.secrets.get / store / delete(key)` | 本插件的密钥，需要 `secrets:own` |

插件进程崩溃不会影响 IDE，IDE 会按 1、2、4 秒退避重新拉起。5 分钟内崩溃 3 次就停止加载，直到「重新加载插件」。

## 5. 可执行文件插件（任意语言）

清单：`"runtime": { "type": "executable", "command": "plugin.exe", "args": [] }`，`command` 必须在插件目录内。

IDE 启动程序后，在标准输入输出上收发 JSON-RPC 2.0 消息，每条消息前加 LSP 风格的消息头：

```
Content-Length: <正文的 UTF-8 字节数>\r\n
\r\n
{"jsonrpc":"2.0", …}
```

插件需要应答的请求：

| 方法 | 应答 |
|---|---|
| `initialize` | `{ "protocolVersion": "0.2" }` |
| `plugin/activate` | `{ "commands": [] }`；参数里有 `id`、`extensionPath`、`storagePath` |
| `commands/execute` | 执行 `params.command`，参数在 `params.args`，返回结果 |
| `plugin/deactivate`、`shutdown` | `null`（`shutdown` 之后退出程序） |

插件可以发给 IDE：`window/showMessage`、`output/append`（通知）、`commands/executeHost`、`secrets/get|store|delete`（请求）。参数格式同 JS 插件（见 `src/main/plugins/pluginProtocol.ts`）。

清单里声明的命令在激活后自动归这个插件，不需要发 `commands/registered`。标准错误输出会进入 IDE 日志。

## 6. 用易语言写插件

在「支持库配置」里勾选 **插件开发支持库**（`lib/ycplugin`），编译成控制台程序，把 exe 作为可执行文件插件。模板：`templates/plugins/eyc-hello`。

| 命令 | 说明 |
|---|---|
| `插件_等待请求 ()` → 文本型 | 等 IDE 发来下一条命令，返回命令 ID。握手、激活由支持库自动处理。返回空文本表示 IDE 要求退出 |
| `插件_取参数数量 ()` / `插件_取参数 (序号)` | 当前命令的参数（序号从 1 开始，非文本参数返回 JSON 文本） |
| `插件_回复 (结果)` / `插件_回复错误 (错误信息)` | 回复当前命令（每条命令回复一次；忘记回复时，下一次「插件_等待请求」会自动回复空结果） |
| `插件_显示消息 (内容, [类型])` / `插件_输出 (内容)` | 输出面板消息 / 编译输出 |
| `插件_执行命令 (命令, [参数])` → 文本型 | 调用 IDE 命令，失败返回空文本，用 `插件_取错误信息 ()` 查看原因 |
| `插件_取插件标识 ()` / `插件_取存储目录 ()` | 插件 ID、可写存储目录 |

```
.判断循环首 (真)
    命令 ＝ 插件_等待请求 ()
    .如果真 (命令 ＝ “”)
        跳出循环 ()
    .如果真结束
    .判断开始 (命令 ＝ “eychello:greet”)
        插件_显示消息 (“你好！”, )
        插件_回复 (“完成”)
    .默认
        插件_回复错误 (“不认识的命令：” ＋ 命令)
    .判断结束
.判断循环尾 ()
```

**不要在插件程序里用「标准输出」**，它是和 IDE 通信的通道。

## 7. 开发与调试

1. 把插件目录放在某个开发目录下，设置环境变量 `YCIDE_EXTRA_PLUGIN_DIRS=<开发目录>`（多个用 `;` 分隔），启动 IDE。
2. 开发目录里的插件不用授权（视同同意了它声明的权限），但仍在受限进程里运行，所以权限问题能提前发现。
3. 改了文件，IDE 会自动重新加载插件；也可以用「工具 → 重新加载插件」。设 `YCIDE_PLUGIN_HOT_RELOAD=0` 可关闭自动重新加载。
4. 「工具 → 插件管理」可以看到每个插件的状态、运行在哪种进程、申请的权限、未启用的原因。

## 8. 发布

1. 生成发布者密钥（只做一次，私钥自己保管）：

   ```bash
   node scripts/plugin-pack.mjs keygen <密钥目录>
   ```

2. 打包并签名，得到 zip 与商店索引条目：

   ```bash
   node scripts/plugin-pack.mjs pack <插件目录> <输出目录> --key <密钥目录>/publisher-private.pem --url-base https://你的下载地址/
   ```

3. 把 zip 放到下载地址，把条目与公钥（`publishers.<发布者>`）提交给商店索引。插件与支持库共用同一个索引，条目的 `kind` 为 `plugin` 或 `theme`。

安装时 IDE 依次检查以下几项，任何一项不通过都拒绝安装：

1. sha256；
2. 发布者签名。公钥首次见到后固定在本机，之后公钥变化即拒绝；
3. 包里 `plugin.json` 的 ID 和发布者与条目一致；
4. 主题包不带代码；
5. 申请的权限不超出用户确认的范围。

未签名的包需要用户勾选「我了解风险」才能安装。
